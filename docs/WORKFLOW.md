# 🔄 CSP 전체 워크플로우

## 📊 시스템 아키텍처

```
입력 데이터 (XLSX)
    ↓
    ├─→ PA (문단 정렬)
    │    ↓
    │    ├─ Target Split (마지막 문장 추출)
    │    ├─ DP Word-boundary (최적 배치)
    │    ├─ Word Span Slicing (무결성 보존)
    │    └─ Integrity Verification (검증)
    │    ↓
    │    PA 출력 (문장병렬)
    │    ↓
    │    PA 평가 (정답 비교)
    │
    └─→ SA (문장 정렬)
         ↓
         ├─ Embedding (BGE 모델)
         ├─ Semantic Matching (유사도 계산)
         ├─ Phrase Annotation (구 분할)
         ↓
         SA 출력 (구병렬)
         ↓
         SA 평가 (정답 비교)
```

## 📂 데이터 플로우

### 입력 데이터 구조

**파일**: `xlsx/{책이름}/{책이름}_문단병렬.xlsx`

| 열 | 설명 | 예시 |
|----|------|------|
| `문단색인` | 문단 고유 ID | 1, 2, 3, ... |
| `원문` | 중국 원문 (여러 문장) | "其執以來，見此君子之實也。是故於文王..." |
| `번역문` | 한국 번역 (여러 문장) | "그 실행한 바를 따라, 이 군자의 진면목을 본다..." |
| `구병렬` | 기존 구 단위 분할 (참고용) | [선택사항] |

## 🔧 PA (문단 정렬) 파이프라인

### 목표
구병렬 **문단** → 문장병렬 **문장**으로 변환

### 알고리즘

#### 1단계: Target Split (마지막 문장 추출)

```
입력: "其執以來，見此君子之實也。是故於文王，不敢變。"

처리:
1. 종료 기호 찾기: "。", "！", "？", """, "】"
2. 마지막 문장 추출: "不敢變。"
3. 나머지 텍스트: "其執以來，見此君子之實也。是故於文王，"

출력:
- 문장들: ["其執以來，見此君子之實也。", "是故於文王，", "不敢變。"]
```

#### 2단계: Dynamic Programming (단어 경계 기반 배치)

```
번역 문장: ["그 실행한 바를 따라, 이 군자의 진면목을 본다.", 
            "따라서 문왕에 대해서", 
            "감히 바꾸지 않을 수 있다."]

원문 단어들: [其, 執, 以, 來, 見, 此, 君, 子, 之, 實, 也, 是, 故, 於, 文, 王, 不, 敢, 變]

DP 계산:
- 각 단어를 번역 문장에 배치
- 최적 매칭 순서 결정
- 단어 스팬(start, end) 계산

예:
- 번역문 1: 단어 0-10 (其 ~ 也)
- 번역문 2: 단어 11-15 (是 ~ 王)  
- 번역문 3: 단어 16-18 (不 ~ 變)
```

#### 3단계: Word Span Slicing (무결성 보존)

```
계산된 스팬을 이용해 원문 추출:

번역문 1 원문 = src_text[word_spans[0][0]:word_spans[10][1]]
              = "其執以來見此君子之實也"

번역문 2 원문 = src_text[word_spans[11][0]:word_spans[15][1]]
              = "是故於文王"

번역문 3 원문 = src_text[word_spans[16][0]:word_spans[18][1]]
              = "不敢變"

✅ 장점: 원본 텍스트에서 직접 추출 → 100% 무결성 보장
```

#### 4단계: Integrity Verification (검증)

```
검사 항목:
1. 길이 비교: 입력 원문 ↔ 출력 원문 (합계)
2. 손실 분석: 어떤 문자가 손실되었는가?
3. 원인 파악: 공백 손실 vs 실제 문자 손실

결과:
- 입력: 12,345 문자
- 출력: 12,319 문자
- 손실: 26 문자 (모두 공백) ✅
```

### 출력 형식

**파일**: `xlsx_pipeline_results/{책이름}/{책이름}_PA_문장병렬.xlsx`

| 열 | 설명 |
|----|------|
| `문단색인` | 원문 문단 ID (참고용) |
| `문장ID` | 생성된 문장 고유 ID |
| `원문` | 분할된 원문 문장 |
| `번역문` | 해당 번역문 문장 |
| `무결성검증` | PASS/FAIL |
| `integrity_losses` | 손실 문자 상세 정보 |

## 🧠 SA (문장 정렬) 파이프라인

### 목표
문장병렬 **문장** → 구병렬 **구**로 분할

### 알고리즘

#### 1단계: Embedding (의미 벡터화)

```
입력 문장: "그 실행한 바를 따라, 이 군자의 진면목을 본다."

BGE 모델 적용:
- 단어 토큰화: [그, 실행한, 바를, 따라, 이, 군자의, 진면목을, 본다]
- 각 토큰 → 768차원 벡터

출력: 768차원 임베딩
```

#### 2단계: Semantic Matching (의미 기반 매칭)

```
원문 임베딩: v1 = [0.1, 0.2, 0.3, ..., 0.8]  (768차원)
번역문 임베딩: v2 = [0.15, 0.18, 0.35, ..., 0.75]

코사인 유사도 계산:
similarity = (v1 · v2) / (||v1|| × ||v2||)
           = 0.95  (0~1 범위, 1에 가까울수록 유사)

매칭 전략:
- 각 원문 구 → 가장 유사한 번역문 구 찾기
- 임계값 이상만 매칭
```

#### 3단계: Phrase Annotation (구 분할)

```
매칭된 구 쌍:
- 그 실행한 바를 | 그 실행한 바를
- 따라 | 따라
- 이 군자의 진면목을 | 이 군자의 진면목을
- 본다 | 본다

의미 경계 감지:
- 문법적 경계 (조사, 조동사)
- 의미적 경계 (동사, 명사 경계)

출력: 구 단위 분할 완성
```

### 출력 형식

**파일**: `xlsx_pipeline_results/{책이름}/{책이름}_SA.xlsx`

| 열 | 설명 |
|----|------|
| `문장ID` | PA에서 받은 문장 ID |
| `구_ID` | 생성된 구 고유 ID |
| `원문` | 분할된 원문 구 |
| `번역문` | 해당 번역문 구 |
| `유사도` | 의미 기반 유사도 |

### 평가 지표

#### 1. Row 매칭 (행 단위)

**PA의 경우**: 소스 기반 스마트 매칭
```python
# 같은 원문을 참조하는 행들 매칭
GT 행 3: "其執以來"
Pred 행 4: "其執以來"
Pred 행 5: "見此君子"

매칭:
- GT[3] ↔ Pred[4] (같은 원문)
- Pred[5]는 다른 GT 행과 매칭
```

#### 2. Token-level n:m Matching

```python
GT    행 1: 原文 = "其執", 번역문 = "그 실행"
Pred  행 1: 원문 = "其", 번역문 = "그"
Pred  행 2: 원문 = "執", 번역문 = "실행"

# 토큰 레벨에서 n:m 매칭
GT 토큰: [其, 執]
Pred 토큰: [其] + [執]

매칭 점수 계산:
Jaccard = |교집합| / |합집합| = 2 / 2 = 1.0 (완벽)
```

#### 3. 유사도 계산

```python
# 각 매칭 쌍에 대해 Jaccard 계산
scores = [1.0, 0.95, 0.88, ...]

# F1 점수 계산
precision = (매칭된 토큰 수) / (예측 토큰 수)
recall = (매칭된 토큰 수) / (정답 토큰 수)
F1 = 2 * (precision * recall) / (precision + recall)
```

### 평가 결과 해석

```
F1 ≥ 80%: ✅ 우수 (대부분의 구/문장이 정확)
F1 70-80%: 🟡 양호 (대부분 맞으나 일부 개선 필요)
F1 50-70%: ⚠️ 개선필요 (심각한 오류)
F1 < 50%: 🔴 심각 (전면 검토 필요)
```
